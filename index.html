01 / Engineering surfaces

Controls that sit outside the model.

The important boundary is not just the prompt. It is the authorization decision made when model output requests a real-world action.

Identity / authorization

Who can an agent act as?

Short-lived workload credentials, least-privilege IAM, per-tool scopes, per-resource authorization, and explicit delegation. Never treat model text as an authorization grant.

AWS IAM / STSOIDCOPA / RegoMCP permissions

Example: a document-reading agent is refused a cross-tenant file read despite having a valid model-generated tool request.

Runtime isolation

Where does generated code run?

Dedicated runtime identities, ephemeral filesystems, read-only mounts, restricted capabilities, syscall filters, no host socket mounts, and strict container lifetimes.

DockerseccompAppArmorgVisor (study)

Example: repository content cannot reach host secrets even after persuading an agent to execute a setup script.

Network / egress

What destinations can tools reach?

Default-deny egress, DNS and destination controls, tenant-aware policies, minimal outbound connectivity, and review of data leaving the trust boundary.

NetworkPolicyeBPF (study)Proxy policyFlow logs

Example: an agent cannot send retrieved private text to an attacker-controlled endpoint.

Detection / telemetry

Can defenders reconstruct an action?

Tie agent run IDs to tool calls, principal, target resource, policy decision and network outcome; aggregate into actionable alerts rather than raw prompt logs.

OpenTelemetryAgents SDK tracesMicrosoft SentinelKQL

Example: alert when a retrieved web page precedes a denied file-access and outbound-POST sequence.

Security evaluation

Does the control survive adversarial inputs?

Versioned attacker-controlled fixtures; tool-policy assertions; regression tests for allowed and denied behaviors; clear denominators for attack success and false blocks.

pytestPyRIT (study)garak (study)MITRE ATLAS

Example: run a benign task alongside an injected one; verify that useful task completion remains possible while prohibited tool calls fail.

Threat modeling

Where can untrusted content gain authority?

Document source→sink paths, privileges, sensitive data, boundaries, plausible abuse, preventive controls, observability and residual risk.

OWASP Agentic 2026OWASP LLM 2026STRIDEAttack trees

Example: a malicious search result proposes a tool invocation that crosses from read-only retrieval into a privileged write operation.

Network plane
Controlled egress

Destination allowlist and outbound policy.

Telemetry plane
Traces + policy decisions

Correlate execution, denials and anomalies.

Security invariant: untrusted_content ≠ authorization. High-impact operations require a trusted authorization path independent of the LLM.

03 / Threat-model case studies

Attack path → invariant → test.

These are illustrative, non-operational scenarios and proposed tests. They are not findings against a production target.

Threat model / illustrative

Indirect prompt injection

illustrative-policy.rego · simplified educational pseudocode / not a deployed policy
package agent.tool

default allow := false

allow if {
  input.principal.scopes[_] == input.request.scope
  input.request.tenant == input.principal.tenant
  input.request.resource in input.principal.allowed_resources
  input.request.destination in input.policy.allowed_destinations
  not input.request.requires_approval
}

# Deny is the safe default. Approval cannot be inferred from model output.

Artifacts to publish: sanitized attack fixtures, expected/actual tool decisions, blocked-action rate, benign-task completion and regressions.
